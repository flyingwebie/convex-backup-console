# Convex Backup Console

One shared, password + 2FA protected console that backs up **many** self-hosted Convex
instances (each deployed from this repo's root `docker-compose.yaml`) to S3-compatible storage
(AWS S3, Cloudflare R2, B2, MinIO…) or a local volume. See [PLAN.md](PLAN.md) for the design.

**Status:** instances, destinations, jobs (manual and cron), keep-last-N retention, export cleanup
on the source, **restore** (same or another instance, typed confirmation), **zip download**, run and
restore history, audit log, and Better Auth login with required TOTP. Tested end to end locally (see
`testing/TESTING.md`). Still to build: age encryption, GFS retention, notifications.

## Deploy in Coolify (once)

1. **New resource → Docker Compose** from this Git repo, branch `main`
   (or `feat/backup-console` while testing), **Docker Compose Location** `/backups/docker-compose.yaml`.
2. **Leave the `app` service without a domain.** Traffic only arrives through the tunnel.
3. Set environment variables:
   - `PUBLIC_URL`: `https://backups.example.com`
   - `ADMIN_EMAIL` / `ADMIN_PASSWORD`: first admin (12+ chars). Only used while no user exists.
   - `TUNNEL_TOKEN`: see below.
   - `SERVICE_PASSWORD_64_MASTERKEY` and `SERVICE_PASSWORD_64_AUTHSECRET` are generated by Coolify.
     **Copy the master key into your password manager.** Without it, the stored admin keys and S3
     secrets can't be decrypted.
4. Deploy, open `PUBLIC_URL`, sign in, and enrol 2FA (it's mandatory).

The image is published by `.github/workflows/backup-console.yml` to
`ghcr.io/flyingwebie/convex-backup-console`. Pin a version with `CONSOLE_VERSION=sha-xxxxxxx`.
If the package is private, add GHCR credentials to Coolify, or make the package public.

## Cloudflare Tunnel + Access

1. **Zero Trust → Networks → Tunnels → Create tunnel** (Cloudflared). Copy the token into `TUNNEL_TOKEN`.
2. In the tunnel: **Public hostname** `backups.example.com` → service `http://app:3000`.
   Cloudflare creates the DNS record.
3. **Zero Trust → Access → Applications → Add → Self-hosted**, hostname `backups.example.com`,
   session duration 24h. Policy: **Allow**, *Include → Emails* = your team list.
   Login method: One-time PIN.

The app never has a public route on the server, so Access can't be bypassed through the server IP.

## Register a new Convex instance (~2 min)

1. Deploy the root `docker-compose.yaml` for the project (`CONVEX_VERSION` defaults to `latest`).
2. In Coolify, open the instance's `backend` terminal and run `./generate_admin_key.sh`.
3. In the console: **Add instance** with the instance's public API URL (`SERVICE_URL_BACKEND`)
   and the admin key. The console checks both before saving.
4. **Add job**: pick destinations, a cron schedule (e.g. `0 3 * * *`, server time = UTC) and how many backups to keep.

## Local development

```bash
cd backups
pnpm install
BACKUP_MASTER_KEY=dev BETTER_AUTH_SECRET=dev-secret-at-least-32-characters-long \
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='a-long-password' pnpm dev
```

State lives in `backups/data/` (git-ignored).
